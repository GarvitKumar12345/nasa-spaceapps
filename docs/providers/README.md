# Data providers — status and boundaries

Source of truth for live status: `GET /api/providers` (rendered in **Methods**), generated by `backend/skyshift/providers/`.
Session 1 (2026-11-14) implemented the synthetic provider; session 2 (2026-11-14) connected SPHEREx DR1 as a read-only
viewer with live checks (see [spherex.md](spherex.md)); session 3 (2026-11-14/15) added Gaia DR3: a recorded field query,
epoch propagation, an overlay and alignment diagnostics of the SPHEREx WCS (see [gaia_dr3.md](gaia_dr3.md)). Facts for
WISE and NEOSSat still come only from the brief's documentation review; **documentation retrieval is not a live API,
download, calibration, or validation test**, and no request to those archives has been made.

Boundary rules (enforced in code): image and catalog providers have separate contracts (`ImageProvider`, `CatalogProvider`
in `providers/base.py`); an unavailable provider raises `ProviderUnavailable` → HTTP 503; nothing ever substitutes
synthetic data for a failed archive request; releases are pinned per record and never switched silently. Observed datasets
declare unavailable analyses in `Dataset.capabilities`; the API answers those routes with 409 `not_available`. Live tests
separate a changed archive row count (recorded as a note in the validation report) from schema, provenance and
pinned-product failures (which fail the test).
