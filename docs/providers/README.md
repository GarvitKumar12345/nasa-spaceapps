# Data providers — status and boundaries

Source of truth for live status: `GET /api/providers` (rendered in **Methods**), generated by `backend/skyshift/providers/`.
Session 1 (2026-11-14) implemented the synthetic provider; session 2 (2026-11-14) connected SPHEREx DR1 as a read-only
viewer with live checks (see [spherex.md](spherex.md)). Facts for Gaia DR3, WISE and NEOSSat still come only from the
brief's documentation review (`planning/SkyShift_Claude_Code_Brief.md`, "Resource analysis"); **documentation retrieval is
not a live API, download, calibration, or validation test**, and no request to those archives has been made.

| Provider | Role | Code status | Live checks | Notes |
|---|---|---|---|---|
| Synthetic (SYN-NB-01) | images + simulated catalog | implemented, tested (see Methods) | n/a | Training data only; never a fallback for archive failures |
| SPHEREx (NASA/IPAC IRSA) | primary images | implemented: DR1 discovery, byte-range screening, cutouts, R7 file validation, read-only viewer | executed 2026-11-14 (`pytest -m live`, 3 tests) | [spherex.md](spherex.md); no SPHEREx measurements yet |

| WISE / unWISE | optional comparison | documented, not implemented | not run | [wise.md](wise.md) |
| NEOSSat (CSA / CADC) | optional case study | documented, not implemented | not run | [neossat.md](neossat.md) |

Boundary rules (enforced in code): image and catalog providers have separate contracts (`ImageProvider`, `CatalogProvider`
in `providers/base.py`); an unavailable provider raises `ProviderUnavailable` → HTTP 503; nothing ever substitutes
synthetic data for a failed archive request; releases are pinned per record and never switched silently. Observed datasets
declare unavailable analyses in `Dataset.capabilities`; the API answers those routes with 409 `not_available`.
